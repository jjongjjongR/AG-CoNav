# ①번 — 실측 기반 측정노이즈(R) 보정

## 0. 요약

`bags/velocity_4m_5mps_attempt1`(실험 #5)의 위치에서 쓰인 이론 기반 R 구간표
(`measurement_noise_max_distances/sigmas = [1,20,50,100] / [0.007,0.010,0.020,0.050]`,
입사각 보정 `1/cos²θ` 고정)를, 같은 시뮬레이터(gpu_lidar, Seongdong_gu_100x100
teleport 월드)에서 정지비행(teleport) 12조건(거리 4×입사각 3) 반복 스캔으로
실측 검증했다.

**결론**: 이 시뮬레이터의 `os1_lidar`는 노이즈가 주입되지 않는 결정론적
레이캐스팅(모델 sdf에 `<noise>` 엘리먼트 없음)이라, 실측된 산포는 (a) range
resolution 0.01m 양자화, (b) 목표 반경 안 지형 미세 요철, (c) 채널/방위각
이산화가 만드는 근소한 히트점 위치 차이의 합성 효과다. 실측 결과 **거리
의존성도 입사각 의존성도 기존 이론표보다 훨씬 약하다** — 실측 σ는 거리
5~84m, 입사각 0~75° 전 구간에서 대략 0.0067~0.0090m(=6.7~9.0mm) 사이에
머물렀고, 이론값(0.007→0.05m, 게다가 `1/cos²75°`≈14.9배 추가 배율)처럼
distance²·1/cos²θ로 급격히 커지지 않았다.

## 1. 방법

- P0 = (-25.0, -100.0, 1.4177) — 건물 없는 순수 지형, 반경 0.5m 실측
  평탄도 std=0.0064m(8회 반복 프로빙)로 검증된 지점. 선정 경위는
  `run_results/calibrate_noise.py` 파일 상단 docstring 참고(1차/2차 후보
  탈락 사유 포함).
- `run_results/calibrate_noise.py`로 각 (거리, 입사각) 조건마다
  `/drone/cmd_pose`(teleport, velocity 절대 미사용) 발행 → TF로 실제 도착
  확인(중요 버그 수정, 아래 2번 참고) → 스캔 최소 50회(달성 실패한 3개
  조건은 예외, 아래 표 참고) 반복 수집 → map 좌표로 변환 후 P0 반경 안
  점들의 z가 GT(1.4177m)로부터 흩어진 정도(표준편차)를 계산.
- 목표 반경은 기본 0.5m, 거리·입사각이 커져 그 반경 안에 점이 하나도
  안 걸리면(레이 간격이 넓어지는 정상적인 기하 현상) 1.0→2.0→3.0m로
  단계적으로 넓혀 재시도(`RADIUS_LADDER`). 반경이 넓어질수록 "센서 노이즈"
  대신 "실제 미세 지형 변화"가 섞여 들어갈 위험이 커지므로, 사용된 반경을
  결과에 함께 기록하고 표 5에서 신뢰도를 구분했다.

## 2. 발견한 버그 — teleport 유실 (수정 완료)

최초 `--pilot`(조건 1개, 스캔 10회) 결과가 명백히 이상했다(range_mean=3.94m,
height_error_mean=0.998±0.969m, 5m/0° 조건인데도). `diag_probe.py`(진단용,
1회성)로 원시 로컬프레임 점을 덤프해 원인을 찾음: 노드 시작 직후 첫
`/drone/cmd_pose` publish가 `drone_pose_controller` 구독자와의 DDS
디스커버리가 끝나기 전에 나가 그냥 유실됐다 — 드론이 실제로는 커맨드한
위치가 아니라 이전 위치(관측된 값: x=-12.2, y=-91.1, **z=84.0** — 이전
84m 실험 때 월드에 남아있던 기본 스폰 pose로 추정)에 그대로 남은 채
스캔을 수집했다. `ros2 service call .../set_pose` 직접 호출로는 즉시
정확히 이동하는 것으로 이 가설을 검증했고, `calibrate_noise.py`의
`teleport()`에 **TF 기반 도착 확인(오차 0.1m 이내, 최대 10초 재시도)**을
추가해 수정했다(수정 후 pilot 재실행: height_error_mean=-0.0001±0.0068m,
정상). 상세 기록은 `run_results/PROGRESS.md`의 "[새 세션]" 절 참고.

### 3-1. 측정 불가/폐기 조건에 대한 판단

거리 20m·50m에서 입사각 75°는 반경 3m까지 넓혀도 P0 근처에 아예 히트가
없었다(레이 간격이 거리·입사각에 비례해 넓어지는 기하학적 결과 —
결정론적 센서라 스캔을 더 늘려도 같은 빔 패턴이 반복될 뿐이라 해결 안
됨). 84m·75°는 반경 3m에서 점은 잡혔지만 height_error가 최대 3.33m로
튀어 순수 지형 노이즈가 아니라 실제 지형 기복/장애물이 섞인 것으로
판단해 폐기했다. 대안(P0를 다른 곳으로 재탐색, 스캔 밀도를 높이는
센서 설정 변경)은 이번 실험 범위(#5 위에 ①④ 얹기, 소스코드는 R
로직만 조정)를 벗어나므로 시도하지 않고, 이 3개 조건은 **모델
피팅에서 제외**하고 표 4의 분석·모델은 신뢰 표시된 8개 조건(순수
0.5m 반경) + 참고용으로만 다룬 2.0m 반경 3개 조건(20/60, 50/60,
84/60 — 굵게 표시 안 한 값들)에 기반한다.

## 4. 분석

### 4-1. 거리 의존성 (입사각 0° 고정)

| 거리(m) | σ(m) |
|---|---|
| 5  | 0.0067 |
| 20 | 0.0063 |
| 50 | 0.0081 |
| 84 | 0.0082 |

5~84m 전 구간에서 0.006~0.008m로 사실상 평탄하다. 기존 표가 가정한
"거리가 멀수록 급격히 나빠진다"(0.007→0.050, 7배)는 이 시뮬레이터에는
해당하지 않는다 — range resolution(0.01m) 양자화가 지배적 오차 원인이라
거리에 거의 무관한 것으로 해석된다.

### 4-2. 입사각 의존성 (거리 5m 고정, 반경 0.5m 신뢰 구간만)

| 입사각(°) | σ(m) | σ/σ₀ 실측 | 1/cos²θ 이론 배율 |
|---|---|---|---|
| 0  | 0.0067 | 1.00 | 1.00 |
| 60 | 0.0088 | 1.31 | 4.00 |
| 75 | 0.0080 | 1.19 | 14.93 |

실측 배율은 이론(1/cos²θ)의 1/3~1/12 수준으로 훨씬 작고, 60°에서
75°로 갈 때 오히려 σ가 살짝 줄었다(0.0088→0.0080) — 두 값 다 50스캔
기준 sub-mm 차이라 사실상 측정오차 범위 안의 잡음이며, **입사각이
이 범위에서 R에 주는 영향은 이론이 예측하는 것보다 훨씬 약하다**는
결론을 강하게 뒷받침한다.

멱함수 σ(θ) = σ₀ / cos(θ)^p 로 피팅하면:
- θ=60°: p = ln(1.313)/ln(2) ≈ **0.39**
- θ=75°: p = ln(1.194)/ln(3.864) ≈ **0.13**

두 추정치가 0.13~0.39로 흩어져 있고 표본이 3점뿐이라 정밀한 지수를
추정하기엔 부족하지만, 공통적으로 **이론값 2.0보다 한 자릿수 작다**는
점은 분명하다. 안전 마진을 감안해 **p=0.3**을 채택한다(0.13~0.39 범위의
중간값에 가깝고, 큰 입사각에서 지나치게 낙관적이 되지 않도록 0에
가깝게 반올림하지 않았다).

## 5. 새 R 모델

`drone_elevation_mapper.py`에 `measurement_noise_incidence_exponent`
파라미터(신규, 기본값 2.0 — 기존 동작·B/기준 변형과 완전히 동일하게
유지)를 추가하고, ①이 적용되는 변형(A/C)에서만 아래 값으로 덮어쓴다.

```yaml
measurement_noise_max_distances: [20.0, 50.0, 90.0, 170.0]
measurement_noise_sigmas:        [0.008, 0.009, 0.010, 0.012]
measurement_noise_incidence_exponent: 0.3   # 기존 고정 2.0 대체
```

- 구간 경계: 실측한 4개 거리(5/20/50/84m)에 맞춰 [20,50,90,170] 사용
  (170m은 OS1-32 최대 사거리, 기존 표도 100m 초과분을 마지막 구간으로
  클램프하던 것과 같은 설계 — 84m을 넘는 관측이 실제로 들어올 수 있어
  마지막 구간을 사거리 끝까지 늘렸다).
- σ 값: 실측 σ(0.0063~0.0082m)에 반올림 + 완만한 안전마진(측정 못 한
  구간·소표본 불확실성 대비, 약 0.001~0.004m)을 얹었다 — 실측값을
  그대로 쓰지 않고 살짝 보수적으로 잡은 이유는 (1) n_points가 적은
  구간(50m: 110점, 84m: 36점)의 표본 불확실성, (2) 20/75·50/75가
  아예 측정 불가했던 데이터 공백에 대한 대비.
- 지수 0.3: 위 4-2 분석 근거. 기존 2.0 대비 큰 폭의 하향 조정이지만,
  실측 3개 조건(0°/60°/75°, 모두 반경 0.5m 신뢰 구간) 모두가 일관되게
  이 방향을 가리켜 근거는 충분하다고 판단.

기존 표(이론 기반)와 비교하면, 예를 들어 84m·75° 조건에서:
- 기존: σ_distance(0.050) / cos(75°)² ≈ 0.050 × 14.93 ≈ **0.746m**
- 신규: σ_distance(0.012) / cos(75°)^0.3 ≈ 0.012 × 3.864^0.3 ≈ 0.012 × 1.505
  ≈ **0.018m**

약 40배 차이. 기존 표는 실제 Ouster OS1-32 데이터시트 스펙(README
근거)이라 **실물 센서라면 여전히 유효할 값**이고, 이번 보정은 어디까지나
"이 시뮬레이터(무노이즈 gpu_lidar)의 실측 특성"에 한정된다는 점을
분명히 남긴다 — 시뮬레이션 실험(A/B/C 비교) 목적에는 이 실측 기반 표가
더 정확하지만, 실물 드론에 그대로 이식하면 안 된다.
