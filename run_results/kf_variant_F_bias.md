# 변형 F — 편향(bias) 진단

## 방법
baseline(local, rate=2.0) 결과 지도(`elevation_map_saver`로 저장한
`/drone/elevation_map` GridMap)를 순수 지형 GT(`gt_traversable.py`의
`terrain_grid`, height_map.png 기반)와 건물 풋프린트를 제외하고 셀별로
직접 비교(`kf_bias_check.py`, 신규). diff = 지도값 - GT지형값.

## 결과
비교 가능한 셀: 611,937개(건물 제외, 둘 다 유효).
| 통계량 | 값 |
|---|---|
| mean | +0.04819 m |
| **median** | **-0.00086 m** |
| std | 0.37650 m |
| p25 / p75 | -0.00173 / -0.00005 m |
| p5 / p95 | -0.00367 / +0.00227 m |
| t통계량(mean/SEM) | 100.13 |

## 판정: **치우침 없음 — 이 방향(전역 보정 항 추가) 기각**

## 해석 (mean과 median이 크게 다른 이유부터 먼저 확인)
t통계량(100.13)만 보면 "극도로 유의한 편향"처럼 보이지만, 이건 표본이
610,000개가 넘어 아주 작은 효과도 통계적으로 "유의"해지는 고전적 함정이다
(큰 표본에서 t-검정은 사실상 항상 유의해진다). **median(-0.86mm)과
p25~p75(-1.7mm~-0.05mm)가 전부 0에 극도로 가깝고 서로 부호도 크게
다르지 않다** — 즉 셀의 대다수(중앙 50%)는 GT와 사실상 완벽히 일치하며
일관된 방향(항상 위/아래)의 치우침이 없다. mean(+48mm)이 이보다 훨씬 큰
이유는 p95(+2.3mm)조차 mean보다 훨씬 작다는 데서 드러나듯, **소수의
극단적 양의 오차(긴 꼬리)가 평균을 끌어올린 것**이지 전체 분포가
이동한 게 아니다. 즉 "baseline이 항상 몇 mm 낮게/높게 잰다"는 가설은
기각된다 — median 기준 오차는 wheel 임계값(80mm)의 100분의 1도 안
된다.

이 긴 꼬리 자체는 흥미로운 별개 현상(건물 경계 인접 셀 등에서 드물게
크게 틀리는 셀들 존재 가능성 — 변형 J의 동기와 연결)이지만, "전역
편향 보정 항"으로 고칠 문제가 아니다(median을 이동시키는 게 아니라
꼬리 자체를 줄여야 하는 문제이므로, 상수 오프셋을 더하는 보정은 이
꼬리에 아무 도움이 안 되고 오히려 median 근처의 이미 정확한 대다수
셀만 어긋나게 만든다).

## 지시사항에 따른 처리
"없으면 치우침 없음, 이 방향은 기각으로 명확히 기록하고 다음으로
넘어가라" — 보정 항 변형은 별도로 구현/테스트하지 않는다.
